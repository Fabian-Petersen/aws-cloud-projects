# AGENTS.md

## Scope and source of truth

This file governs the Atlantic Meat backend in this directory. Reusable Terraform
infrastructure modules are available at `../../modules/` for context.

`terraform.tfvars` is the Terraform input source of truth for the intended DynamoDB
tables, Lambda packaging metadata, API Gateway routes, queues, and EventBridge
subscriptions. It is not proof of the resources currently deployed; use a reviewed
`terraform plan` to establish that. `API_Docs/openapi_20260417.yaml` and the other dated OpenAPI files
are useful API references, but do not cover every route currently configured in
Terraform. Update both the Terraform route map and the relevant API documentation
when changing a public endpoint.

`terraform.tfvars`, `tfplan`, `.terraform/`, and state files are local deployment
artifacts. Do not expose their values, commit credentials, or hand-edit Terraform
state.

adding an import that Terraform will not package.

## Application architecture

- API Gateway REST resources are always rooted at `/api`. Parent and child paths
  come from `api_parent_routes` and `api_child_routes`. `api` is reserved and must
  not be added as a parent route. Child routes use an explicit `parent_key` and a
  `level` of 1–3.
- Non-`OPTIONS` API methods are AWS proxy integrations. Methods configured as
  `COGNITO_USER_POOLS` receive Cognito claims via
  `event.requestContext.authorizer.claims`; `OPTIONS` routes use `NONE` and a mock
  response. Most handlers return `{statusCode, headers, body}` with a JSON-string
  body.
- The configured domains are jobs, assets, transfers, users, comments,
  notifications, admin, and dashboard. Route implementation names are mapped to
  deployed Lambdas in `terraform.tfvars`; adding a Python file alone does not
  deploy or expose it.
- The application uses Cognito user pools and groups. Handlers commonly derive
  `sub`, name, email, and `cognito:groups` from the authorizer claims. Do not trust
  client input for identity-derived fields; preserve each handler's authorization
  and group/location filtering behavior.
- S3 upload URLs are generated by API Lambdas and `s3FileUploadLambda` consumes
  `ObjectCreated:Put` events. Its key layouts are functional contracts:
  `maintenance/{id}/...`, `maintenance_action/{id}/...`, `invoices/{actionId}/...`,
  `assets/{id}/...`, and `transfers/{transferId}/invoices/...` or
  `transfers/{transferId}/assets/{index}/images/...`. It resolves the table sort
  key before appending file metadata, so changing a key schema also requires
  updating this Lambda.
- Every table with `enable_stream = true` is wired through an EventBridge Pipe to
  the custom bus. The module applies the configured `stream_filter` (defaulting to
  `INSERT`) and routes matching bus events to configured SQS or Lambda targets.
  SQS then invokes the configured transfer/notification consumers. The EventBridge
  module also creates a 3-day event archive and catch-all CloudWatch log target.
- The API transfer handlers use lower-case states `pending`, `approved`,
  `in-transit`, and `completed`, with conditional DynamoDB updates. Approval
  removes a one-time EventBridge Scheduler reminder, while the request-notification
  handler creates it using SSM-provided scheduler values. Preserve the event
  payload shape, table keys, status casing, and conditional-write logic together.
- `pdf_lambda/` is independent of the ZIP Lambdas. It is an ECR container image
  triggered from the maintenance-request DynamoDB stream; on a `MODIFY` where the
  status changes to `complete`, it reads the linked action and writes a jobcard PDF
  to `crud-nosql-app-images/jobcards/`.

## DynamoDB model and access constraints

Table definitions live in `dynamodb_tables` in `terraform.tfvars`; names in that
map receive the `-table` suffix. Important key/index contracts include:

- Maintenance requests: `id` / `jobCreated`; GSIs on status, status+jobCreated,
  location+jobCreated, `action_id`, and `assetID`+jobCreated.
- Maintenance actions: `id` / `actionCreated`; GSIs on location+actionCreated and
  assetID+actionCreated.
- Assets: `id`; GSIs on `assetID`, `serialNumber`, and `location`.
- Transfers: `transferId` / `transferCreated`; GSIs for status, requestor,
  approver, and recipient views.
- Notifications: `recipientSub` / `notificationCreated`, with entity/status GSIs.
  The table map contains per-table TTL-looking fields, but the module actually
  drives TTL from its global `enable_ttl` and `ttl_attribute` inputs; do not assume
  nested table fields enable TTL. Comments use `request_id` / `createdAt`; users and
  locations use `id` and `location` respectively.

Use the complete partition-and-sort-key pair for `get_item`, `update_item`, and
`delete_item` on composite-key tables. Existing handlers often query by partition
key first to discover a sort key; do not replace a GSI query with a scan when the
index supports the access pattern. Several list handlers deliberately paginate
`scan` or `query` responses via `LastEvaluatedKey`; preserve pagination. DynamoDB
numbers are `Decimal`, so JSON responses need the local conversion helper.

When adding or changing a table/index, make the matching updates in the handler's
`dynamodb_permissions`. The ZIP Lambda module generates least-privilege table ARNs
from this map and grants index access only when `allow_index_access = true`.

## Lambda and Terraform conventions

- API/DynamoDB Lambdas are Python 3.12 in the configuration. A function entry
  specifies `file_name`, `handler`, optional `path`, `invoked_by`, DynamoDB
  permissions, and optional metadata. The handler value must match the
  module filename and `lambda_handler` function.
- ZIP packaging archives a single `source_file` at
  `lambdas/{path}/{file_name}` (or `lambdas/{function-name}/{file_name}` if no
  path). Do not introduce local package dependencies without changing the packaging
  design; the only checked-in Python requirements are for `pdf_lambda`.
- Custom Lambdas use `lambda_functions_custom` for environment variables, timeout,
  inline IAM statements, and managed-policy attachments. S3 upload processing is
  separately configured by `s3_event_lambda` and its module.
- Do not rely on the `statements` blocks currently present in some
  `lambda_functions` entries: `modules/lambda/modules/dynamoDB` only creates
  DynamoDB policies from `dynamodb_permissions`, Lambda-invocation policies from
  `lambda_permissions`, and managed-policy attachments from `extra_policies`.
  It does not consume `statements`. Add/attach an actual policy before adding a
  new non-DynamoDB AWS API call to one of these functions.
- IAM and event wiring are configuration, not inferred from code. If a handler
  starts calling S3, SSM, Cognito, Scheduler, EventBridge, SQS, or another Lambda,
  add the minimal required policy and triggering/invocation configuration at the
  same time.
- The provider configuration uses named local AWS profiles and an assumed role;
  the S3 backend uses an encrypted, lockfile-enabled S3 state backend. Never run
  applies against an unknown account/profile.
- `terraform apply` can create or change API Gateway, Cognito, DynamoDB tables and
  streams, EventBridge resources, queues, Lambda functions, DNS/SES records, and
  the PDF ECR deployment. Inspect a saved plan before applying.

## CORS, API, and response conventions

Many handlers support both REST API Gateway event variants when determining the
HTTP method and CORS origin. Follow the target handler's existing response helper
and allowed-origin list. Do not return a Python dict as `body` from an API handler:
API proxy responses use `json.dumps`. Keep `Content-Type`, credentials, allowed
methods, and preflight behavior aligned with the route's configured methods.

Path parameter names must match the Terraform path part and handler lookup (many
current routes use `{id}` even where documentation names it `{jobId}` or
`{assetId}`). Check `api_child_routes` before renaming a parameter. The OpenAPI
snapshots currently use paths without the Terraform-managed `/api` prefix; verify
against Terraform before relying on a documentation-only route.

## Existing contract mismatches to assess before extending

The project contains transfer and notification implementations that use different
generations of field and index names. This is a compatibility constraint, not a
reason to silently rename fields:

- The current Terraform transfer table key is `transferId` / `transferCreated` and
  includes `TransferStatusIndex`; several transfer event consumers still read `id`
  and `assetID`, and two API handlers query an `IdIndex` that is commented out of
  the table configuration.
- Notification table consumers use `recipientSub` / `notificationCreated` and an
  `id` attribute. `handleTransferNotifications` additionally writes
  `notificationCreatedAt`; retain `notificationCreated` in produced records so the
  table key and read/update handlers remain valid.
- The EventBridge table object accepts `event_detail_type` (underscore). One asset
  verification entry uses `event_detail-type` (hyphen), which is not the module's
  declared attribute. Use the declared spelling for new or corrected entries and
  confirm the resulting Pipe configuration in `terraform plan`.

When touching any of these paths, trace the API writer, table key/index definition,
stream event, EventBridge rule, queue target, and consumer together. Do not make a
single-sided rename or introduce a new status spelling.

## Development and verification

Run Terraform commands from this directory:

```powershell
terraform fmt -check -recursive
terraform init
terraform validate
terraform plan -out=tfplan
terraform show tfplan
```

Only run `terraform apply tfplan` after confirming the AWS account, profile, and
planned resources. `terraform plan`/`apply` rewrites `tfplan` and other local
artifacts; do not include those in a code-only change.

There are no discovered automated unit/integration tests or test runner configs.
For a syntax-only check of a changed standard-library/Boto3 handler, run from this
directory:

```powershell
python -m py_compile lambdas/<domain>/<function>/<function>.py
```

The PDF Lambda is the exception and has its own dependencies and container flow:

```powershell
cd pdf_lambda
python -m pip install -r requirements.txt
docker build --platform linux/amd64 -t pdf-lambda .
docker run -p 9000:8080 pdf-lambda
```

Its local invocation endpoint is
`http://localhost:9000/2015-03-31/functions/function/invocations`. A realistic
event requires DynamoDB Stream `Records` with `OldImage` and `NewImage`; the
handler ignores non-`MODIFY`, unchanged-status, and non-`complete` events.
